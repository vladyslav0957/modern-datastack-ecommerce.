# Modern Data Stack - Онлайн-кінотеатр (Лабораторна робота №1)

Комплексний інженерний проєкт у рамках дисципліни Технології сховищ даних (Індивідуальний варіант 14: Онлайн-кінотеатр).

## 1. Архітектура та Суть Проєкту
Проєкт реалізує сучасну парадигму ELT (Extract, Load, Transform). На першому етапі вирішуються завдання видобутку та завантаження транзакційних даних (OLTP) у сирий шар сховища даних:
- **Extract (Видобуток):** Генерація імітаційних даних за допомогою Python (Faker) для сутностей: directors, movies, subscribers, views, та 
reviews (з імітацією пропущених значень та бізнес-правил).
- **Data Lake (Озеро даних):** Збереження проміжних даних у форматі .parquet.
- **Load (Завантаження):** Первинне завантаження повного набору даних у схему 
raw аналітичного сховища (DWH) без трансформацій ("as is").
- **Інфраструктура:** Розгортання локального середовища бази даних PostgreSQL (версія 15) за допомогою контейнеризації Docker.

## 2. Структура репозиторію
- data_generator.py — основний Python-скрипт генерації даних та їх завантаження в DWH.
- docker-compose.yml — конфігурація для підняття контейнера PostgreSQL.
- requirements.txt — список необхідних бібліотек Python.
- .gitignore — файли та каталоги, які виключені з контролю версій.

## 3. Інструкція з запуску проєкту

Клонуйте репозиторій та створіть віртуальне середовище Python, після чого активуйте його:
'python -m venv venv'
'venv\Scripts\activate'

Встановіть необхідні залежності:
'pip install -r requirements.txt'

Запустіть локальне сховище у фоновому режимі через Docker:
'docker compose up -d'

Виконайте скрипт генерації та завантаження даних у Raw-шар:
'python data_generator.py'

## Лабораторна робота №2: Analytics Engineering та трансформація даних за допомогою dbt Core

### Мета роботи
Опанувати процес трансформації «сирих» даних всередині DWH (етап Transform у парадигмі ELT) за допомогою dbt Core та SQL, побудувати розмірнісну модель даних (Схема «Зірка») для предметної області "Онлайн-кінотеатр".

### Архітектура та структура dbt-проєкту (`cinema_dbt`)
У межах роботи побудовано двошарову архітектуру трансформації у схемі `analytics`:

1. **Staging-шар (`models/staging/`)** — первинне очищення та приведення типів даних:
   - `stg_directors.sql` — очищення даних про режисерів.
   - `stg_movies.sql` — фільтрація некоректних цін (`price_per_view > 0`).
   - `stg_subscribers.sql` — обробка `NULL`-значень в email (`coalesce`) та дедуплікація записів (`row_number()`).
   - `stg_views.sql` — приведення типів дат переглядів та часу перегляду.
   - `stg_reviews.sql` (джерело `ratings`) — нормалізація оцінок та відгуків.

2. **Marts-шар (`models/marts/`)** — вітрини даних за схемою «Зірка» (Star Schema):
   - **Таблиці вимірів (Dimensions):** `dim_directors`, `dim_movies`, `dim_subscribers`.
   - **Таблиця фактів (Fact Table):** `fct_views` (містить ключі вимірів, метрики переглядів та вартість фільму).

### Результати виконання
- Налаштовано підключення через `profiles.yml` до бази `cinema_dwh` у Docker.
- Успішно виконано трансформацію та матеріалізацію моделей у схемі `analytics` за допомогою команди `dbt run`.

## Лабораторна робота №4: BI, Data Governance та оптимізація

### Виконані завдання та архітектура
1. **Business Intelligence (Metabase):**
   - Розгорнуто сервіс аналітики **Metabase** у контейнері Docker (додано сервіс `metabase` до `docker-compose.yml` із прокиданням порту `3000`).
   - Налаштовано підключення до аналітичного сховища PostgreSQL (`cinema_dwh`) за внутрішнім ім'ям хоста `dwh_postgres`.
   - Побудовано аналітичний дашборд на основі вітрин зі схеми `analytics` (`fct_views` та `dim_subscribers`), який включає:
     - **«Динаміка переглядів»** — лінійний графік кількості переглядів у розрізі дат (`view_at`).
     - **«Топ-5 підписників за кількістю переглядів»** — стовпчаста діаграма, побудована шляхом об'єднання (`JOIN`) таблиці фактів `fct_views` та виміру `dim_subscribers`.

2. **Data Governance (Docs as Code та Data Lineage):**
   - Створено конфігураційний файл метаданих `models/marts/schema.yml` з описами вітрин даних, колонок та тестами цілісності (`unique`, `not_null`).
   - За допомогою команд `dbt docs generate` та `dbt docs serve` згенеровано інтерактивну документацію та граф залежностей (**Data Lineage**), що відображає повний шлях трансформації даних від сирого шару (`raw`) через `staging` до фінальних вітрин (`marts`).

## Загальні висновки по проєкту
У межах виконання циклу лабораторних робіт спроєктовано та реалізовано повноцінний наскрізний конвеєр даних (**End-to-End Data Pipeline**) для предметної області **«Онлайн-кінотеатр»** відповідно до сучасної парадигми **ELT (Extract, Load, Transform)**:

* **Інфраструктура та видобуток (Python + Docker + PostgreSQL):** розгорнуто ізольоване середовище сховища даних, реалізовано генерацію транзакційних даних із збереженням реляційних зв'язків, збереження у форматі `.parquet` та завантаження у шар `raw`.
* **Трансформація та моделювання (dbt Core + SQL):** очищено «сирі» дані у шарі `staging` та побудовано класичну розмірнісну модель **«Схема Зірка» (Star Schema)** у шарі `analytics` (таблиця фактів `fct_views` і таблиці вимірів `dim_subscribers`, `dim_movies`, `dim_directors`).
* **Оркестрація (Apache Airflow):** автоматизовано послідовне виконання всіх етапів завантаження, трансформації та тестування якості даних у вигляді єдиного графа завдань (**DAG**).
* **Візуалізація та контроль даних (Metabase + dbt Docs):** забезпечено бізнес-аналітику через інтерактивні дашборди та прозорість архітектури завдяки автоматично генерованій документації й графу **Data Lineage**.
